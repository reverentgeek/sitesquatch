SiteSquatch has a website now, and you're standing in it! Building it with ssqch made a great field test: every rough spot we stepped on is smoothed out here, along with a few that turned up while testing on several migrations.

## The headlines

- **A home on the web.** [sitesquatch.dev](https://sitesquatch.dev) has the docs, every example site running live, and a Markdown copy of each docs page for coding agents. Search for a name you know (`base`, `imagePlugin()`) and its card comes first.
- **Feeds that know where they live.** Serving your site under a path? `absoluteUrl(post.url, site.url)` adds it for you, so your feed's links land on the right pages. Redirects under a path work now, too.
- **Computed values can see more.** A computed value can read `collections` and actually get them, and a computed `layout` can pick each page's layout.
- **The same dates in every checkout.** Set `dateFallback: "git"`, and a page without a date takes the date of its last commit, so a fresh clone stops reshuffling your sitemap. Not every mystery in the woods needs to stay one.

## What you might need to change

- **`ssqch docs` reads the new docs pages.** Every name still answers with the same text. A script that reads its output will see some sections a level higher, links to `.md` pages, and `--from` naming the trailhead's page on sitesquatch.dev.
- **`assetsPlugin()` leaves no plain copy behind.** A listed file that's also a passthrough copy keeps only its fingerprinted name. HTML links are rewritten as before; anything else that loads the plain path (an `import` in another JavaScript file, a `url()` in CSS) needs `assetUrl("/assets/site.css")`.
