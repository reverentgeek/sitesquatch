We asked an agent to build Pack Mule, a packing-list planner: a static site with a small app on top, written in TypeScript, that works offline and runs under a strict Content-Security-Policy. It found where ssqch's job ends and someone else's JavaScript takes over, and this release smooths that edge.

## The headlines

- **Live reload hears every save.** An edit made the moment a page opened could slip past the browser. Now each page knows which build it came from, so nothing gets missed.
- **Live reload works under a strict policy.** The reload script and its error overlay are files now, not inline code, so `script-src 'self'` lets them through.
- **Pictures validate.** `imagePlugin()` writes `sizes` the way HTML allows, including on images you mark `loading="eager"` above the fold.
- **Types for your browser code.** `ssqch types --schemas-only` gives a page's scripts the site's schemas, without the config's Node types.
- **Every example in the box.** All twelve example sites come with the package. `ssqch docs examples` says what each one shows.
- **Fewer quiet surprises.** A build tells you when a `width` attribute kept your `widths` from making any copies, `ssqch patrol` stops treating fetched HTML pieces as pages, and a docs search that comes up empty points you at the sections that have your words.

## What you might need to change

- **Your config's `afterBuild` now runs after the plugins' hooks**, so it sees the finished output. The link checker still runs last. If a hook of yours has to run before a plugin's, move it into a plugin listed before that one: `plugins: [{ name: "first", afterBuild: myHook }, ...]`.
