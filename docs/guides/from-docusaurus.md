# Moving from Docusaurus

Docusaurus sites are React apps that happen to render documentation; ssqch builds the same documentation as static HTML that needs no JavaScript to read. The move is mostly mechanical for Markdown pages, and takes a decision for each React component: an Edge component, a container, or client-side JavaScript that stays.

Two examples are distilled from reactnative.dev: [`versioned-docs`](../../examples/sites/versioned-docs/) (versions, sidebars, tabs, a blog with authors) and [`component-docs`](../../examples/sites/component-docs/) (components in place of MDX, live examples).

## The config

| Docusaurus | SiteSquatch |
| --- | --- |
| `docusaurus.config.js` | `ssqch.config.js` |
| `docs/`, `blog/`, `src/pages/` | Folders in the input (`src/docs/`, `src/blog/`), and templates for the other pages |
| `static/` | `passthrough: [{ "static": "." }]` |
| `@docusaurus/plugin-sitemap` | `sitemapPlugin({ url })` from `ssqch/sitemap` |
| `@docusaurus/plugin-client-redirects` | `redirectsPlugin({ redirects })` from `ssqch/redirects` (real pages or `_redirects` lines, not client-side redirects) |
| Algolia DocSearch, or a local search plugin | [Pagefind](https://pagefind.app) after the build: `afterBuild: { run: "npx -y pagefind --site dist" }` (see the `docs-sidebar` example) |
| `themeConfig.prism` | `markdown: { highlight: true }`; colors from `/highlight.css` and its `--hl-*` properties |
| `onBrokenLinks: "throw"` | `linksPlugin()`: broken links and anchors fail production builds |
| `i18n` | Not yet |

## Docs, versions and sidebars

| Docusaurus | SiteSquatch |
| --- | --- |
| `versioned_docs/version-1.0/` and `docs/` (next) | `src/docs/1.0/` and `src/docs/next/`, each with directory data (`{ "version": "1.0", "layout": "doc.edge" }`) |
| `versions.json` | `_data/versions.json`, for the version switcher |
| `sidebars.js` | `_data/sidebars/<version>.json`, or a `_data/sidebars.js` that exports the same object. `navTree(sidebar, page.url)` marks the current page, `navPager` gives previous and next, `navBreadcrumbs` the trail. |
| Autogenerated sidebars (`sidebar_position`) | `nav: { parent, order }` front matter and `pagesTree(collections.docs)` |
| `id`, `slug` | `permalink` |
| `sidebar_label`, `sidebar_position` | The sidebar data, or `nav: { title, order }` |
| `hide_table_of_contents` | A front-matter flag your layout checks before `toc(page.headings)` |
| `tags` | `tags` |
| `last_update` (git) | `lastModified: "git"` in the config, then `page.lastModified` |

## Markdown and MDX

| Docusaurus | SiteSquatch |
| --- | --- |
| `:::note`, `:::tip Title`, `:::warning[Title]` | Containers, with the same `:::` syntax: `_includes/containers/note.*` renders them (the title is `container.args`) |
| `<Tabs>` and `<TabItem value="npm">` | `:::: tabs` holding `::: tab npm` containers (see `versioned-docs`) |
| A code block's `title="App.js"` and `{1,4-6}` | `{1,4-6}` marks lines with `highlight: true`; `title=` reaches a `fence` hook as part of `fence.info` |
| Live code blocks, `SnackPlayer` fences | A `fence-<lang>` hook (`_includes/hooks/fence-SnackPlayer.edge`) that writes the embed |
| MDX `import` and JSX components | Edge components in the Markdown: `@component('components/callout', { type: 'warning' })...@end` (the page's Markdown runs through Edge first). Components that need React in the browser stay client-side JavaScript (web components work well). |
| `<!-- truncate -->` in blog posts | `<!-- more -->`, then `page.excerpt` |
| `authors.yml` | `_data/authors.json` (or `.yml`), looked up by the post's `authors` |
| `{#custom-id}` headings | The same |

## React pages

Pages in `src/pages/*.js` become templates in any of ssqch's languages. Interactive parts (a playground, a live demo) stay JavaScript: ship them as a script on the page that needs them, or as a web component.
